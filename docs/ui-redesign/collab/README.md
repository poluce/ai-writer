# 多助手编排概念稿（agent 与 agent，参考）

> 说明：这组稿子解决的是 **agent 与 agent 之间的分工编排**（委派、排队、审批、团队室），不是"人与写作助手共同写内容"。后者见 [../coop/](../coop/)。本目录保留为参考。

本目录按现有能力梳理多助手调度模型：**项目助手负责编排，架构助手、章节蓝图助手分工执行；忙碌时排队复用会话；所有写入都要经过确认卡；计划模式先给方案，写作模式才落盘。**

三套概念稿固定同一套皮肤（纸墨书卷 2.0），差异只来自协作模型。

## 现有能力（设计依据）

| 能力 | 现状 |
| :--- | :--- |
| 助手角色 | 项目助手（`general`）、架构助手（`architect`）、章节蓝图助手（`blueprint`）、界面助手（全局作用域） |
| 委派 | 项目助手可把任务委派给架构助手、章节蓝图助手，目标助手会话优先复用 |
| 排队 | 目标助手忙碌时排队，不新建碎片会话 |
| 确认卡 | 工具调用需用户批准后才执行，卡片按所属会话回传 |
| 双模式 | 计划模式出 Diff 供审阅；写作模式静默落盘 |
| 受控写入 | 领域事实只能通过 `novel_config`、`story_architecture`、`propose_chapter_blueprint`、`GenerateDraftCommand` 等 Seam 修改 |
| 会话 | 项目作用域存于项目目录，全局助手存于应用数据目录，互不干扰 |

## 协作原则

1. **人是导演，不是提示词输入框**：助手分工执行，人负责目标、裁决与批准。
2. **每个动作可追溯**：谁提出、谁执行、谁批准、何时写入，一屏可见。
3. **计划与执行分离**：提案 → 审阅 → 落盘三段式，对应现有计划 / 写作模式与确认卡。
4. **并行有秩序**：运行、等待确认、排队、空闲四种状态必须可见；忙碌的助手不应被静默并发。
5. **冲突显式化**：两个助手给出不同方案时，由人裁决，不做后端静默合并。
6. **作用域可见**：项目助手 / 架构 / 蓝图共享项目上下文，界面助手不携带项目事实。

## 模型一 · 指挥台（Director Console）

![指挥台](collab-1-director.png)

以**协作时间线**为主轴：用户指令、委派、提案、冲突提醒、工具确认卡都在同一条时间线上；左侧是助手状态与队列，右侧是待确认与产物清单。

- 委派以独立卡片呈现（项目助手 → 章节蓝图助手），谁把任务交给了谁一目了然；
- 提案卡带 Diff 行与采纳 / 在画布中修改 / 否决；
- 工具确认卡以"批准执行 / 查看变更"呈现，对应现有确认机制；
- 队列显示等待原因（如"等待架构助手让出"），对应会话复用与排队语义；
- 计划 / 写作模式常驻输入框，默认计划模式。

**适合**：作为协作的默认中枢，替代当前右侧单助手面板。

## 模型二 · 共创画布（Co-creation Canvas）

![共创画布](collab-2-cocreate.png)

协作发生在**文档内部**，而不是侧栏聊天里：

- 行内建议以浅底 + 虚线标注，Tab 采纳、Esc 忽略；
- 两位助手对同一节拍给出不同方案时，直接并排成"冲突卡"，由人选择 A / B / 都保留；
- 页边批注来自架构助手，可应用修改、忽略或跳转；
- 选区工具条提供润色、检查设定、让助手重写，对应"选中即操作"；
- 右侧是协作动态与召唤助手，而不是完整聊天记录。

**适合**：正文与蓝图的精细共创；与模型一可以并存——指挥台负责流程，画布负责落笔。

## 模型三 · 助手团队室（Agent Team Room）

![助手团队室](collab-3-team-room.png)

把每个助手当成一个**席位**同时展示：

- 四个席位分别显示当前任务、进度、最近两条对话、产物与操作（展开 / 暂停 / 接管）；
- 主控席显示编排步骤（规划 → 委派中 → 汇总 → 交稿）；
- 右侧是审批队列、任务队列与团队广播输入；
- 人类可以随时接管某个助手，或暂停/广播整个团队。

**适合**：多任务并行、需要监视多个助手时；也是"多 agent"感最强的一版。

## 与现有实现的映射

| UI 概念 | 对应现有机制 |
| :--- | :--- |
| 时间线中的委派卡 | 项目助手 → 架构/蓝图助手的子会话委派 |
| 助手状态（运行/等待/排队/空闲） | 会话复用 + 忙碌排队 |
| 待确认 / 审批队列 | 工具确认卡与写入门禁 |
| 计划 / 写作开关 | 计划模式 Diff 审阅 / 写作模式静默落盘 |
| 提案卡与 Diff | `propose_chapter_blueprint`、`novel_config`、`story_architecture` 等领域 Seam |
| 产物清单 | 蓝图、草稿、审稿任务等派生结果 |
| 作用域标签 | 项目助手 / 架构 / 蓝图 vs 全局界面助手 |
| 接管 / 暂停 | 子会话联动终止与重新指派 |

## 建议组合

- **默认中枢**：模型一（指挥台），取代右侧"单助手聊天面板"；
- **文档形态**：模型二（共创画布），用于正文与蓝图编辑；
- **监视图**：模型三（团队室），用于多任务并行或批量章节创作。

三者共用同一套助手状态与确认语义，可以按场景切换视图，而不是做成三个割裂的功能。
