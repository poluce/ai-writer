# 主 Agent 架构概念稿（单一入口 + 委托 + 下钻）

本目录按以下架构实现人机协作：

- **用户只需要和主助手对话**；
- 主助手可以**自己直接修改内容**；
- 也可以**调用工具，把修改任务委托给架构助手、章节蓝图助手等子助手**；
- 子助手的修改**回到主助手汇总**，用户默认仍只在主助手这里确认；
- 如果需要精细修改，用户可以从委托卡**下钻到某个子助手**，直接和它对话，结束后回到主对话。

三张图是同一套界面的三个状态：主对话直接改、委托子助手、下钻子助手。皮肤与前面轮次一致（纸墨书卷 2.0）。

> 代码基线：`main` @ `a17bddf`（v0.1.4）。实现现状与差距见 [CODE-REVIEW.md](CODE-REVIEW.md)：委派、复用排队、计划/写作模式、确认卡在后端已存在；缺的是委托结果结构化、统一确认、父子会话链接和下钻 UI。

## 状态三 · 下钻到子助手

![下钻到子助手](lead-3-drilldown.png)

- 点击委托卡上的"直接和架构助手说"，右侧面板切换为**下钻态**：
  - 顶部是子助手会话（架构助手 · 由主助手委派），可直接对话；
  - 上方保留主助手的**收起条**：已暂停 · 观察中，附一句"你们聊完把结论带回来"；
  - 一条提示说明"消息会同步给主助手，退出后自动回到主对话"；
- 子助手可以在**具体段落**上做精细修改：时间线修正、加一句钟响埋妹妹出场；文内以"架构助手 · 直接修改"标注，行内浅黄高亮；
- 修改卡给出"应用并返回主助手 / 只应用第 1 处 / 忽略"；
- 顶部栏和状态栏都明确"主助手已暂停"；返回后，结论与变更自动带回主会话。

## 交互规则

1. **单一入口**：右侧对话面板默认只属于主助手。子助手不主动弹窗、不抢焦点、不单独占用一个聊天列表。
2. **直接修改优先**：能在主助手这一层改的，就由主助手直接改，用变更卡说明改了什么、可撤销。
3. **委托可见但克制**：委托只以一张折叠卡出现在时间线里，显示子助手、任务、状态、结果摘要；用户不需要理解子助手的全过程。
4. **统一确认**：无论改动来自主助手还是子助手，都在主助手会话里确认；子助手不直接向用户要确认。
5. **下钻是例外通道**：只有用户主动点"直接对话"才进入子助手会话；此时主助手暂停并观察，退出时把结论/变更带回主会话。
6. **子助手问题默认上抛**：子助手需要澄清时，把问题作为工具结果交回主助手，由主助手决定是否问用户，避免多 agent 噪音；只有下钻时用户直接回答子助手。
7. **作者归属可见**：文档内标注主助手 / 子助手 / 用户的修改，可逐条撤销。
8. **写入仍走受控 Seam**：子助手只能产出提案或补丁，实际落盘由主助手合并、经确认卡提交，沿用现有领域工具与原子写。

## 状态机

| 层 | 状态 | UI 表现 |
| :--- | :--- | :--- |
| 主助手 | 空闲 / 运行中 / 等待你确认 / 已暂停（下钻） | 对话头部标签、输入框、状态栏 |
| 子助手 | 未启动 / 运行中 / 等待输入 / 已完成 / 失败 | 委托卡状态、进度条、回报摘要 |
| 文档 | 无改动 / 已应用 / 待确认提案 / 冲突 | 变更条、段落标注、行内高亮 |

## 建议的工具与数据约定

- `delegate_task({ agent, task, scope, context, return_format })`：由主助手调用，创建或复用子会话；返回 `{ status, summary, proposals[], artifacts[] }`；
- 子助手返回的是**提案/补丁**，不是直接写入；主助手负责合并与提交；
- 子会话由主助手持有，下钻只是 UI 附着到该会话；退出时把结论作为一条工具/摘要消息写回主会话；
- 所有变更保留来源标识（主助手 / 子助手 / 用户），供撤销与审计。

## 需要拍板的点

1. 下钻采用**同一面板切换**（本稿）还是**分屏并排**？本稿选前者，保证主助手始终是唯一入口。
2. 子助手是否允许"直接改正文"，还是只能产出提案？本稿允许下钻后直接改，但默认仍经确认应用。
3. 下钻期间主助手是否允许继续被用户说话？本稿为暂停 + 观察，避免两个会话并行。
