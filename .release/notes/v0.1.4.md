> 延续独立发行线：应用身份（appId、productName、安装目录、更新通道）与旧版互不覆盖；

## 核心变更 / Core Highlights

### 1. 审稿助手全面接管 AI 审稿 / Review Assistant Takes Over AI Review
- **专属只读助手与入口**：新增第 4 个专属助手——审稿助手（review assistant），在右侧工具栏新增常驻入口面板；采用 `review-` 前缀隔离存储与恢复独立会话。
  A new dedicated review assistant is introduced with a permanent entrance on the right toolbar; sessions are isolated with the `review-` prefix.
- **只读沙盒与安全契约**：明确审稿助手只读定位，挂载连续性事实与只读版本管理工具，杜绝裸写；唯一写工具 `submit_chapter_review` 严格执行 `ReviewContract` 结构化契约，并依托 `expectedSource` 防脏写并发保护。
  The review assistant operates with a read-only toolset to prevent unintended mutations; its only write tool, `submit_chapter_review`, strictly enforces the `ReviewContract` schema with `expectedSource` snapshot protection.
- **草稿编辑器联动与旧链路清理**：草稿编辑器正文保存后自动切入审稿助手面板发起审稿；物理移除旧版单体审稿工作流命令及相关废弃链路。
  The draft editor switches seamlessly to the review assistant upon saving; obsolete workflow review commands and legacy pipelines are completely removed.

### 2. 模块间低耦合与单体文件解耦 / Architectural Decoupling & Module Cohesion
- **消除循环依赖与视图反向污染**：在 Store 与 Service 间引入生命周期钩子注册缝，通过共享快照镜像解除对 Store 的直接反向依赖；抽象 `dialog-port` 隔离破坏性弹窗与告警视图。
  Eliminated cyclic dependencies between Stores and Services using lifecycle hooks; abstracted dialog ports to prevent deep UI coupling.
- **消灭千行以上超大单体**：将模型设置、草稿编辑器、审稿报告、大纲细纲等大体积组件全面拆解为职责单一的受控子组件与纯计算模块。
  Decomposed giant components (Settings, Draft Editor, Review Report, Outline Editor) into focused subcomponents and pure logic modules.
- **分层守护测试**：建立 `layering-contract.test.ts` 契约，基于 Tarjan 算法在 CI 中硬性守护全局 0 运行时依赖环。
  Enforced a strict DAG runtime dependency graph (0 cyclic dependencies) with Tarjan SCC verification.
